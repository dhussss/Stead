# Stead

Dan's whole-life system: a headless core over plain markdown files, with a web app on top.

Before changing behaviour, read `docs/constitution.md` (how the system must behave) and
`docs/item-format.md` (the file format). The discovery record that produced them is the Claude Doc
"Second Brain Rebuild: Discovery". `docs/status.md` says what's done and what's next; update it
at the end of each session.

## Rules for building

- Files are the source of truth. Every write goes to the file first, then the index. The database
  must always be rebuildable from the files (`Vault.rebuildIndex`). Never store something only in Postgres.
- Nothing deletes. `FileStore` has no delete method; keep it that way.
- Keep the core headless. `packages/core` must not import from Next, React or Supabase, so a
  native app can sit on the same core later. Adapters (Supabase storage, Postgres index) live
  outside the core or behind its interfaces.
- Every row is owned. New tables get an `owner` column and row-level security in the same migration.
- Timestamps carry an offset and default to Australia/Perth.
- Unknown frontmatter fields are preserved on every read and write.
- Ground rule 1 applies to code too: if a feature needs babysitting to keep running, it isn't done.

## Layout

```
packages/core   item model, file format, vault (file-first writes), links, urgency. Tested with vitest
apps/web        Next.js 15 app (React 19). Reads the vault through the core
supabase/       migrations: the index tables, usage tracking, the private vault bucket
sample-vault/   example vault generated by scripts/seed-sample.mts
docs/           constitution and file format
```

## Commands

```
pnpm install
pnpm test                       # core tests
pnpm typecheck
pnpm --filter @stead/web dev    # web app on localhost:3000, reading sample-vault/
npx tsx scripts/seed-sample.mts # regenerate the sample vault
```
